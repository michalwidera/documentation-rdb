# Regenerating xretractor plans

Run `./regen/pic_and_qry.sh` from the documentation repository root. The script uses `../retractordb/build/Debug/src/retractor/xretractor`; to select another current executable, set `XRETRACTOR=/path/to/xretractor`. Before use the script runs `ninja xretractor` in the build directory, so figures always come from the current `src/`; an executable given through `XRETRACTOR` is not rebuilt.

Each `.rql` file is the source for at least one figure or code listing in the book.
The script writes listings to `regen/out/`, which mdBook inserts into the marked code
blocks using `{{#include ...}}`. DOT figures are written directly to `assets/`.
Every SVG generated by the script has a transparent background (`xretractor -p`).

`dedup.rql` feeds `dedup_po.svg` (Fig. 38). The script draws Fig. 37 (`dedup_przed.svg`) from the hand-written `dedup_przed.dot`, because the compiler cannot show the plan before deduplication, not even with `RDB_OPT_DEDUP_SUBSTRATES=OFF`: the final topological sort indexes queries by name and merges both `STREAM_ADD_core0_core1` substrates into one node. After a change to `dedup.rql` or to the node style in `presenter::graphiz()`, the `.dot` file has to be updated by hand.
